# FlowerStudio：UI 方向与分批实现讨论稿

状态：用户认可总体布局，作为 UI 细化基线；具体入口、视觉实现、交互细节与开发批次继续讨论。

更新日期：2026-10-12

关联文档：[功能模块讨论稿](functional-modules.md)。

最新调整：产品名称统一为 FlowerStudio。当前交互草案中的插画仅表达布局；正式花材应采用写实方向。视觉路线详见 [写实视觉路线讨论稿](visual-strategy.md)，需在工程方案定稿前验证。

差异化候选：围绕用户已有花瓶与实际插花场景组织入口，具体功能及留存验证见 [差异化与用户留存讨论稿](differentiation-retention.md)，尚未加入已确认范围。

## 1. 讨论顺序

先确认大致 UI、页面结构与主要交互，再从页面流程反推模块职责和实现批次，最后确定工程方案。

UI 确认包括页面布局、导航、编辑方式、关键状态和手机上的组织方式。颜色、字体和素材细节可以随后调整。

正式开发前先形成一版可执行的 UI 风格基线：颜色、字体、间距、圆角和控件，加上桌面 / 手机插花配置页设计稿。配置页是第一张完整业务页面；其他页面复用相同规范逐步实现。写实样片用于校准画布和操作细节，详见 [工程实施 S0](implementation-plan.md)。

## 2. 已确认的产品约束

- 第一版完成设计与采购清单，验证用户设计体验。
- 自动排布与手动拖动同时支持，共用一份设计。
- 免登录试用与本机保存，登录后支持跨设备保存。
- 图片识别第二批接入。
- 支持家庭花瓶插花与手持花束，当前先以花瓶插花展示 UI。
- 产品名称为 FlowerStudio，写实花材及可信的搭配效果是重点方向。
- 已确认先对比固定视角写实与可旋转 3D 样片，之后再定视觉路线。
- 当前总体布局已获认可；最终通过设计清单连接商家购买，交易方式尚未确定。

## 3. 建议的视觉方向

关键词：自然、温柔、清楚、容易上手。

- 页面采用浅色、带一点暖感的背景；适配深色外观时保持相同层次。
- 主操作采用植物绿，粉色与奶白主要来自花材本身。
- 首页留白较多，用一幅花艺画面和模板引导用户开始。
- 编辑器保持清晰分区，优先展示画布、花材配方和下一步操作。
- 使用少量圆角与细分隔线，减少装饰对花材判断的干扰。
- 标题可带一点花艺工作室的气质，操作文字以易读为先。
- 当前草案的花材是示意插画，正式方向已更新为写实；照片切图、预渲染和实时 3D 的选择需另行验证。

## 4. 两种入口方案

### 方案 A：灵感优先（建议默认）

首次进入首页，展示推荐模板和“从零搭配”。选择模板后进入编辑器。

桌面编辑器：左侧花材选择，中央画布，右侧配方与支数。

适合希望先得到搭配帮助的插花新手。首页负责降低开始设计的难度，编辑器负责调整。

### 方案 B：创作优先

首次进入工作台，展示默认搭配，用户立即开始调整。

桌面编辑器：较宽的中央画布，右侧配方，花材选择放到画布下方。

适合目标明确或经常回来设计的用户。仍保留首页、图鉴和作品入口。

两种方案的差别是入口与信息摆放，不需要分别建设两套业务模块。可以在首页与回访入口使用不同起始页面；此行为待确认。

## 5. 用户页面结构

### P01 发现灵感 / 首页

主要内容：

- 品牌与一句话说明。
- 推荐搭配展示。
- “从推荐开始”和“从零搭配”两个入口。
- 模板列表，展示名称、色系、花材组成和支数。
- 简单风格筛选。

主要行为：选择模板 → 创建独立设计 → 进入工作台。

对应模块：M01 花材库、M02 灵感与模板。

### P02 设计工作台

顶部：作品名称、保存状态、设计场景选择、保存草稿、查看清单。

核心区域：

- 花材选择：查看素材，点击添加，后续可扩展搜索与分类。
- 画布：展示当前设计、选中对象与编辑反馈。
- 配方：按花材展示支数，支持增减，进入采购清单。
- 操作工具：编辑方式切换、重新排布、撤销；选中对象后展示对应操作。

交互原则：

1. 自动与手动切换不新建作品、不清空配方。
2. 直接拖动画布对象时，清楚显示已进入手动编辑。
3. 增减支数同时更新配方与画布对象。
4. 拖动、旋转和前后层次调整不改变采购数量。
5. 重新排布是明确的用户动作；处理手动布局和锁定的规则待定。
6. 花瓶与手持场景共用配方；场景的布局、花器及包装规则分别维护。
7. 画布显示搭配参考说明。

需要后续细化的状态：空白、正在编辑、本机已保存、云端保存中、保存失败、素材缺失、对象选中。

对应模块：M01、M03 设计与编辑、M06 作品管理、身份与文件公共能力。

### P03 采购清单

这是由当前设计进入的结果页，不需要成为一级导航。

主要内容：设计名称、花材小图、名称、颜色、支数、购买说明、搭配缩略图。

主要行为：返回修改、复制、导出。

交互原则：

- 导出包含生成时的设计与清单信息。
- 用户修改设计后，可以生成新清单。
- 导出格式待确认，当前草案只展示入口。
- 第一版不需要价格、商家、购物车或付款按钮。

最终形态扩展：清单页提供“查看可购买方案”，展示供货商家、实际购买数量、缺货替代和确认报价，再进入可用购买渠道。详见 [商家与购买流程](purchase-journey.md)。首版仍先验证设计与清单，不提前展示未经确认的购买能力。

对应模块：M05 采购清单，引用 M01 花材与 M03 设计数据。

### P04 我的作品

主要内容：本机 / 账号保存状态提示，作品卡片、缩略图、名称、最近修改时间。

主要行为：继续编辑、新建设计、复制、删除；登录后保存到账号。

交互原则：

- 访客有可用的作品页，登录入口解释跨设备保存的价值。
- 明确区分本机保存与账号保存。
- 登录时导入本机草稿的方式及冲突处理待定。
- 跨设备保存不默认包含多人协作或实时共同编辑。

对应模块：M06 作品管理、身份与权限。

### P05 花材图鉴

主要内容：花材图片、名称、颜色、主花 / 配花 / 叶材等角色、简单搭配与养护说明。

主要行为：查看资料，加入当前设计。

工作台中的花材选择与图鉴共用数据，图鉴可以展示更完整的资料。

对应模块：M01 花材库。

## 6. 导航与管理页面

用户一级导航建议：发现灵感、设计工作台、花材图鉴、我的作品。

登录放在导航右侧；采购清单从工作台进入。

运营管理使用单独入口，在后续 UI 轮次细化：

- 花材管理：资料、素材、发布状态。
- 模板管理：封面、配方、布局、发布状态。
- 反馈列表：问题说明及用户主动关联的作品。
- 基础体验记录：支持验证设计完成和清单生成。

管理页主要面向维护效率，复用业务模块的数据与规则。

## 7. 手机端方向

交互草案在窄屏下将画布、花材选择、配方上下排列，确保内容可访问。

正式手机布局建议进一步讨论：

- 画布作为主要区域。
- 花材选择、配方和对象操作采用可展开面板，避免长页面反复滚动。
- 保存和清单动作有清楚、稳定的位置。
- 拖动、旋转等手势需要避免与页面滚动冲突。
- 桌面与手机共用设计数据及编辑规则，分别组织控件。

手机面板形态尚未确认，不将当前上下排列方式视为最终 UI。

## 8. 从 UI 反推工程边界

页面组织与业务模块不是一一对应。例如工作台使用花材、编辑与保存三个模块；图鉴与工作台共用花材库。

建议分清三类职责：

- 页面与控件：负责用户看到的布局、操作入口和状态反馈。
- 业务规则：负责花材数量、设计变更、自动布局、清单汇总等规则。
- 外部能力：负责本机 / 云端保存、文件、账号及后续 AI 服务。

这样调整三栏布局、改成底部花材面板或更换保存方式时，可以保留核心业务规则。

正式工程设计需要明确公共的设计数据格式，使配方、布局、场景、缩略图和清单可以稳定衔接。

## 9. 按可使用流程分批实现（建议）

本节保留 UI 讨论时的增量草案。最新工程推进划分见 [工程结构与实施路线](implementation-plan.md)，以 S0、S1、S2 统一表达阶段。

### 视觉验证阶段 V：在正式编辑器前验证路线

选择少量代表性花材及一个花瓶，先对比固定视角写实和实时 3D 的实际效果、交互与设备性能。验证结果决定下述 A 阶段的素材及渲染方案。

此阶段应形成可运行样片与测量结果，不将一张 AI 生成的效果图视为 3D 编辑能力的证明。

### 第一版 A：完成一次设计与清单

交付：少量模板首页、基础花材选择、双模式编辑器、两种场景的基础预览、清单展示与复制、基本本机草稿。

先使用少量已准备好的花材和模板，通过正式数据约定接入；后续扩大内容时不改变编辑流程。

验收：用户从模板或空白开始，调整花材和支数、手动摆放，生成正确清单，并在刷新后恢复本机草稿。

说明：当前聊天中的交互草案用于讨论布局，不代表上述能力已经工程实现。

### 第一版 B：完善编辑与作品体验

交付：完整的撤销重做、对象编辑操作、图鉴、作品列表、复制删除、明确的清单导出形式，以及手机上的主要流程。

验收：用户可以持续修改和管理多个作品；桌面与手机的核心流程可用。

### 第一版 C：接入账号与内容运营

交付：登录、云端作品保存、跨设备读取、本机草稿导入流程，花材和模板管理、基础反馈记录。

逐步扩展到计划中的花材和模板规模。

验收：用户可以在另一台设备恢复作品；运营者可以更新花材和模板；旧作品的查看与清单不被内容修改破坏。

A、B、C 是第一版内部增量，不改变已确认的第一版支持登录后跨设备保存的目标。

### 第二批 D：参考图识别

交付：上传入口、识别进度与失败状态、结果确认与修正，将确认的初稿交给同一个编辑器。

验收：识别结果可修正，识别失败可继续手动设计，其他创作入口正常可用。

上线顺序和每批具体操作范围将在 UI 确认与模块细化后定稿。

## 10. 需要先确认的 UI 决策

2026-10-12 已形成[工作台设计基线](workbench-design-spec.md)和[桌面 / 手机设计稿](../artifacts/workbench-design/README.md)：沿用三栏桌面组织，手机采用画布优先与底部展开面板作为当前建议。图片与 3D 路线继续通过网页对照样片确定。下列问题作为原讨论记录保留。

1. 默认入口采用灵感优先还是创作优先。
2. 桌面工作台采用左侧花材三栏布局，还是画布优先、底部花材布局。
3. 是否认可自然、温柔、植物绿的视觉方向。
4. 手机主要采用展开面板还是独立步骤页面。
5. 花材写实路线采用照片切图、多角度预渲染、实时 3D，还是分阶段结合。

确认以上方向后，再细化每个页面的状态、交互与模块实现。
