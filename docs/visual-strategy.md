# FlowerStudio：写实视觉路线讨论稿

状态：研究与建议，尚未确定正式渲染路线。

日期：2026-10-12

## 1. 已确认的方向

- 产品名称统一为 FlowerStudio。
- 用户希望花材写实，插花视觉作为体现竞争力的重点。
- 产品同时支持花瓶插花和手持花束，UI 优先展示花瓶插花。
- 用户提出 Flority 作为参考，并希望讨论是否使用 Blender 制作真实模型。
- 已确认先对比固定视角写实与可旋转 3D 的样片，再确定路线。
- 写实设计最终需要连接商家购买；视觉实例应能对应花材配方和采购单位，详见 [商家与购买流程](purchase-journey.md)。

此前插画草案只表达交互与页面组织，不作为正式花材的视觉标准。写实需求取代文档中将照片级呈现整体延后的建议。

## 2. Flority 的已核实信息

参考网站：[Flority](https://flority.digital/)。

从公开页面和页面源内容观察：

- 使用花材图片与花器图片进行画面组合。
- 提供花材搜索和分类、拖放、尺寸、旋转、透明度、翻转、图层顺序和删除。
- 支持背景选择与作品分享入口。
- 当前公开页面包含作者 Instagram 链接，未找到 GitHub 仓库链接；本次检索也未确认对应的开源仓库或素材许可。

结论：可以用作交互和视觉参考；是否直接复用代码或素材，需要先取得具体仓库及对应授权信息。当前不将其当作已经确认可以复用的开源依赖。

## 3. 分开讨论写实程度与空间能力

固定视角的照片切图可以有很强的实物质感，但不具备完整的空间信息。

实时 3D 可以提供前后侧视角和空间遮挡，但画面是否写实仍取决于模型、纹理、花瓣材质、灯光及后处理。

两类验收分别进行：

- 外观：花型、颜色、开放度、叶脉、自然差异与灯光是否可信。
- 空间：插入点、花茎方向、花器比例、前后遮挡、整体体积是否合理。

真实质感不意味着实际插出的作品一定与预览一致。

## 4. 候选实现路线

| 路线 | 花材素材 | 可获得的体验 | 主要限制 |
| --- | --- | --- | --- |
| A 写实 2D | 真实照片透明切图，同一花材有多个自然变体 | 固定视角搭配、移动、平面旋转、前后图层 | 缺少背面和侧面信息，单张图自带光影会限制自由组合 |
| B 多角度预渲染 | 在 Blender 制作模型并从若干角度渲染透明素材 | 统一光线与比例，离散角度切换，轻量呈现 | 角度有限，不能自然解决任意视角与花材之间的空间阴影 |
| C 实时 3D | Blender 制作或整理模型、纹理与材质，导出网页资产 | 转动整束花、改变花茎姿态、真实深度遮挡与空间观察 | 素材制作、浏览器渲染适配、资源体积和手机性能需要验证 |
| D 交互与成图分开 | 实时场景编辑，并增加可选的离线高质量渲染 | 编辑时流畅，保存时获得更高质量效果图 | 需要渲染任务、资源和等待状态；不是首版默认能力 |

写实 2D 是真实能力路线，不预先认定为低质量。实时 3D 也不预先认定为一定更写实。需用同一花材与构图对比。

## 5. Blender 的职责

Blender 可以承担资产制作：建模、修整采购或扫描所得模型、制作纹理材质、统一比例、建立花型变体、预渲染和导出。

两种交付方式：

1. 输出多角度图片，网页使用这些图片搭配。
2. 输出 glTF / GLB 模型资产，由浏览器渲染引擎呈现和操作。

Blender 不需要在用户每次拖动花材时运行。浏览器的即时编辑应由网页渲染层完成。

若以后提供最终离线高质量成图，后台可以运行渲染任务；这是独立扩展。

导出后需要重新验证网页材质和灯光。Blender 的所有材质节点及场景灯光不能默认在网页中原样再现。

参考：

- [Blender glTF 导出说明](https://docs.blender.org/manual/en/latest/addons/scene_gltf2.html)：支持模型、材质、纹理等导出，并说明材料与灯光的支持范围。
- [Khronos glTF](https://www.khronos.org/gltf/)：面向运行时的 3D 资产传输与加载格式。
- [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)：浏览器渲染方案中的一个可评估加载工具，尚未确定为项目技术选型。

## 6. 花材资产需要的规范

建议明确以下属性，再开始批量素材制作：

- 花材标识、颜色、品种和开放度。
- 单个资产对应一支花、一根叶材还是一组植物；与采购单位保持明确映射。
- 花头直径、花茎长度、整体尺寸和计量单位。
- 插入点、花茎轴向及花头朝向。
- 花型变体：同品种需要适度自然差异，避免整束花明显重复。
- 可用视角或 3D 模型、纹理、缩略图等资产引用。
- 素材来源、许可记录、资产版本和发布状态。
- 网页加载体积、简化版本及设备降级资源。

花材库拥有名称和采购含义；视觉资产通过稳定标识与花材关联。

## 7. 推荐的视觉验证

先选少量代表性资产，例如玫瑰、康乃馨、尤加利与一个不透明花瓶。它们分别覆盖层叠花瓣、复杂花头和叶材。

建议制作两个可运行样片：

- 固定视角写实：照片切图或统一预渲染素材。
- 实时 3D：同样配方，支持观察正面、侧面与背面。

比较内容：

1. 单支花和整束花是否具有真实质感，是否出现重复模型感。
2. 增减支数、前后遮挡与不同视角是否体现搭配变化。
3. 花头、花茎及花器比例是否合理。
4. 首次加载、拖动、转动和手机运行是否流畅，记录实际资源体积与帧率。
5. 每增加一种花材的制作、维护和授权成本。
6. 素材升级后，旧作品是否可以继续呈现。

两套样片尽量采用相同配方、构图、背景及光照目标。避免把不同艺术质量造成的差异误认为技术路线优劣。

具体性能阈值与目标设备在样片开始前确认，不在未测量时承诺性能或成本。

## 8. 对 UI 的影响

目前左侧花材、中央画布、右侧配方的组织仍可采用。

若采用实时 3D，需新增并清楚区分：

- 转动整体观察视角与移动单支花材。
- 花茎姿态、插入位置和长度等对象操作。
- 前视、侧视等快捷视角。
- 花器的实际比例，避免只通过任意缩放获得不合理的“好看”。

选中对象时再展示局部操作，让默认页面优先呈现设计效果。具体交互方式待样片验证后确定。

## 9. 对模块与架构的影响

建议新增 M09“视觉资产与场景呈现”，内部区分资产加工流程、资产发布与加载、渲染器三个职责。

候选边界：

- M01 花材库：花材的业务含义、分类、资料和采购单位。
- M03 设计与编辑：用户设计、花材实例、配方及编辑命令。
- M09 视觉资产与场景呈现：素材及其技术描述，场景的呈现、拾取、视角与资源管理。
- M06 作品管理：保存稳定设计数据与所需资产版本。
- M05 采购清单：从配方汇总采购信息，不依赖渲染器。

需要共享的逻辑是“这一份设计有哪些花材实例”。具体保存平面坐标还是空间坐标、是否需要姿态和花茎参数，应在路线验证后确定。

不承诺任意 2D 设计可以无损转换为 3D。平面素材缺少的空间信息需要模板、默认规则或用户补充。

模块接口应支持选择渲染方案，但不预先实现全部渲染器。首版可部署为一个工程中的清晰模块。

## 10. 更新后的批次建议

1. 先完成视觉路线验证，确定资产规范、目标设备和渲染方案。
2. 用少量高质量花材完成模板 → 设计 → 清单 → 本机保存。
3. 完善对象编辑、手机体验与素材覆盖。
4. 接入账号保存、运营管理及基础反馈，完成第一版目标。
5. 第二批接入参考图识别。

写实质量的验证提前进行，花材数量可以逐步扩展。
