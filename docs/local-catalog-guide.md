# 本地花材库维护指南

日期：2026-10-13。状态：本地资料导入与网页图鉴已接入；云数据库和管理后台尚未接入。

## 当前可用内容

花材图鉴载入 104 条产品或候选、135 条名称关系和 70 条尺寸证据。支持按名称／别名／编号搜索、按大类和多选角色资料筛选、查看来源及季节口径。

工作台保留原 6 个编辑示例及其保存 ID，另新增 10 个本地 Blender 花材试点，共 16 个可选模型。15 个示例关联到 13 个产品类别；红花石蒜暂未匹配 Excel 产品，仍可在原工作台使用。关联仅代表类别／品种参考，不代表尺寸或商家同款已核实。

目前 13 个产品类别有编辑示例，其中 10 条已加入真实参考照片及来源；91 条尚无封面，94 条尚无真实参考照片。新照片和模型保留本地参考状态，待核项和缺图项仍明确显示。十模型的版本、来源及限制见 [试点记录](../artifacts/flower-pipeline/pilot-10-20261014/README.md)。

## 文件分工

| 文件／目录 | 职责 | 是否直接手工修改 |
| --- | --- | --- |
| 根目录参考 Excel | 花材来源资料 | 维护时按现有表头填写，保留产品 ID |
| `data/catalog/overrides.json` | 人工补充的名称、角色、条件和备注 | 可以修改；不会被 Excel 空白覆盖 |
| `data/catalog/assets.json` | 图片／模型版本、对应产品与现有编辑示例 | 可以修改；发布前会验证文件引用和关联 |
| `data/catalog/catalog.json` | 最新完整结构化资料 | 自动生成，不手工修改 |
| `data/catalog/import-report.json` | 最近一次发布批次的数量、变更和缺口 | 自动生成，不手工修改 |
| `data/catalog/sources/<hash>.xlsx` | 导入时的原始 Excel 归档 | 自动复制，保留原文件字节 |
| `data/catalog/snapshots/<revision>` | 完整资料及导入报告的历史快照 | 自动生成，保留旧版本 |
| `public/catalog/index.json` | 当前公开目录入口 | 自动生成，发布时最后切换 |
| `public/catalog/releases/<revision>` | 对应版本的目录和按花材拆分的详情 | 自动生成，保留旧版本 |
| `public/assets` | 当前本地网页图片、模型 | 新素材使用新的文件路径，保留旧文件 |

`data/catalog` 的原表归档和人工资料不在网页公开目录中；部署时按私有资料管理。`public/catalog` 只包含要供网页读取的发布数据。

## 日常资料更新

1. 修改 Excel 中已有产品资料，保留原产品 ID。新增行分配一个新的唯一 ID，例如 `P105`，不按当前行号重新编号。
2. 人工复核内容可以写入 `overrides.json`，独立于来源表。
3. 执行 `npm run catalog:preview`。这一步只检查和计算变更，不写入发布文件。
4. 确认预览后执行 `npm run catalog:import`，生成资料和版本目录。
5. 重新打开网站的“花材图鉴”，读取最新目录。已打开的详情仍使用原目录版本，避免读到混合批次。

导入工具只使用 Python 标准库，无需额外安装 Excel 解析包。项目命令优先寻找已有的 Codex Python，其他环境可使用 Python 3.10+。直接运行示例：

```text
python tools/import_catalog.py --preview
python tools/import_catalog.py
```

不同工作簿可指定来源：

```text
npm run catalog:preview -- -Workbook "D:\资料\新花材库.xlsx"
npm run catalog:import -- -Workbook "D:\资料\新花材库.xlsx"
```

重复导入相同资料会得到相同版本，不生成重复产品，不重写已有相同文件。批次报告保留首次发布该版本时的变更记录；再次执行时，命令输出会显示本次相对当前库的变更数量。

## 人工补充示例

以下是格式示例，需按实际复核结果填写；不是已审核结论：

```json
{
  "schemaVersion": 1,
  "products": {
    "P001": {
      "roles": ["主花", "配花"],
      "roleStatus": "reviewed",
      "roleNotes": "在适合的作品规模中可兼任，具体用途按花头体量确认。",
      "notes": "这里填写人工补充的说明。"
    }
  }
}
```

支持补充字段：`name`、`roles`、`roleStatus`、`roleNotes`、`notes`。角色状态可为 `pending`、`project-suggestion`、`reviewed`。不能在补充文件中更改产品 ID，也不能指向不存在的产品。

## 添加和更新图片

先把图片存入新的路径，例如 `public/assets/catalog/P001/photo-v1/cover.webp`，再在 `assets.json` 的 `assets` 数组中增加一项：

```json
{
  "id": "p001-photo-v1",
  "version": 1,
  "productId": "P001",
  "variantId": "p001-photo-reference",
  "kind": "photo",
  "publicationStatus": "approved",
  "authorizationStatus": "reviewed",
  "mappingStatus": "category-reference",
  "coverUrl": "/assets/catalog/P001/photo-v1/cover.webp",
  "sourceUrl": "填写实际照片来源页面",
  "author": "填写实际作者",
  "license": "填写已核对的许可或授权记录",
  "notes": "写明图片对应品种、颜色和开放阶段，以及未核实的部分。"
}
```

未完成核对时使用 `publicationStatus: "pending"`，这类资产不会进入图鉴。已发布照片必须有来源、作者和许可记录。新照片可以放在该产品建模参考条目前，成为默认封面；没有 `editor` 的照片不会被当作可添加的单支素材。

替换封面或模型时使用新素材 ID、新版本和新文件路径，替换清单中的当前条目，保留旧素材文件；旧发布版本仍引用原文件。相同素材 ID 的已发布文件引用不能原地更改。工具记录本地素材的文件校验值，发现相同版本的文件字节被覆盖时也会停止发布；远程文件无法在本地校验，需要使用不可变的远程版本路径。

已有模型均保留原本的本机预览用途和待核许可状态。本轮没有把它们认定为正式对外发布合格素材。正式云端发布前需单独核对使用范围。

## 导入检查与失败处理

- 产品 ID 重复、别名或素材指向不存在的产品，会停止导入。
- 误删当前库已有产品，会停止发布，先处理停用或迁移关系。
- 文件不存在、文件路径越界、已发布资产原地改引用，会停止导入。
- 角色的条件性描述保持待核定；自然花期不转换成实际库存。
- 上限、下限及严格小于等数值性质保留，空白不变成零。
- 尺寸证据按原物种／品种／商品保留为参考池，不自动用于全部子类。
- 无法确定的月份描述保留原文，列入报告；跨年月份区间会标记跨年。

以上校验在写入前执行。新详情文件准备完成后才切换公开目录入口；失败时原入口仍可读取。当前维护流程按单个导入任务执行，不同时运行多个发布任务。

## 上线时如何迁移

本机的资料结构和 ID 可以迁移到 PostgreSQL，图片与模型可上传到对象存储。原始 Excel、完整快照和授权材料保持私有；经过核对的图鉴图与网页模型进入公开文件库。

目前 `public/catalog` 随网站部署。如果仍采用这套静态发布方式，上线更新需要上传完整新版本目录，再切换目录入口；不能只上传新入口而漏掉详情。先在本机准备、核对，再发布。

接入管理后台和数据库后，让后台写入新资料与素材引用，审核发布后更新缓存，便能实现资料更新不重新部署网站。网页的数据读取已封装在 `src/modules/catalog/library.ts`，可替换为接口读取；无需重做图鉴页面。

迁移时保留所有旧版本文件，不把原始 `.blend` 或私人授权文件放入公开 bucket。现有作品仍使用原 6 个编辑 ID；未来新增品种和模型时需要扩展编辑器支持并定义作品中的素材版本，不能仅导入图鉴条目就当作可编辑模型。
