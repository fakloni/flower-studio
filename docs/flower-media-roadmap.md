## 每项花材需要哪些图片

图鉴第一阶段至少收集一张清楚的真实代表图，优先再补完整单支和花头特写。类别图标明展示的具体品种、颜色与开放阶段；不能用普通菊花替代乒乓菊，也不能用单瓣代替重瓣。

用于 3D 的视图建议单独采集：同一支花的正、左、背、右四张；花头俯视与花托近景作为辅助资料另存。保持对象姿态、光照、背景、拍摄距离和裁切比例一致，完整保留茎底、叶片及侧枝。拍摄记录里另存实际枝长、花头宽高和花头数量，照片本身不能可靠提供实物尺寸。

网络上的同品种照片可以帮助理解结构，只有确认是同一标本的一致视图，才标记为真实多视角建模输入。细节图、同角度裁切和模型渲染都分别标记。

资产记录建议增补：`viewType`、`specimenId`、`captureSetId`、`mediaOrigin`（real-photo / ai-image / model-render）、品种／颜色／阶段、对应产品范围、尺寸核实状态、来源及复核状态。当前候选记录已保存 `viewType` 和视觉检查意见；这些字段还未接入正式图鉴的数据类型。

## imagegen 与 Blender 如何配合

imagegen 能生成或编辑参考图、单支透明示意图、材质参考及多角度候选图，输出的是图片。它不直接输出 GLB 或具有真实花瓣几何的 Blender 模型。独立生成的不同角度可能出现叶片位置、花瓣数量、枝条形状变化；即便画面相似，也需要逐视图检查结构一致性。

两条实际路线：

1. 真实照片 → 必要时 imagegen 生成补充参考视图 → Tripo／Meshy 生成候选模型 → Blender 修茎叶、花瓣及花托、优化材质与面数 → GLB＋模型多角度渲染。
2. 真实照片 → Blender 手工或参数化建立花瓣、花托、茎与叶结构 → imagegen 提供材质参考或外观目标 → Blender 调整材质并导出。规则形态先验证这一条，复杂重瓣花需要更多制作工作。

从同一合格模型渲染出的多角度图有共同几何依据，适合统一工作台素材；它们仍是模型渲染，不能作为实物照片或品种核实证据。[Blender Geometry Nodes](https://docs.blender.org/manual/en/4.3/modeling/geometry_nodes/introduction.html) 可处理网格、曲线与实例，支持构建可调几何结构。

花材细茎、薄花瓣、密集分枝是本项目需要专门测试的对象。AI 模型可能出现花瓣粘连、背面封闭或枝叶融合，此处是风险判断，尚无本轮生成结果支持优劣排名。把照片贴到平面上只能提供特定角度的视觉效果，不等同于可从背面观察的完整花材模型。

## 推进顺序

第一批图鉴采集 16 项：乒乓菊、鲜切绣球、绿毛球、银莲花、芍药、花毛茛、金鱼草、补血草、龟背叶、单瓣／重瓣洋桔梗、单头康乃馨、银叶桉、标准非洲菊、白花马蹄莲、六出花。已找到精确品种图的 Atlanta／Annecy 同步整理。

13 个缺封面产品处于待核名状态，先核对实物或供应商标签。已有模型参考的 P069 也待核物种。九星叶、贯众叶、掌、柔丽丝、天鹅绒等不凭市场名猜测物种或生成“真实参考”。

3D 第一轮建议只试 3 项：Atlanta 非洲菊（放射花瓣）、白花马蹄莲（曲面结构）、单头康乃馨（复杂重瓣）。这三项分别检验结构可控性与生成细节，先取得或制作整支参考，再进行外部生成或本地建模；本轮只完成路线与输入缺口整理。

验收检查：一支对应的实际花头数、整支完整性、茎底插入点、米制尺度、正侧背花型、花托与叶片结构、薄花瓣背面可见性、贴图完整性、浏览器旋转和多支叠加效果。花瓣双面材质及透明贴图按 [Blender glTF 导出规则](https://docs.blender.org/manual/ja/4.5/addons/import_export/scene_gltf2.html) 检查，最终仍在网页里验证。

每个合格模型统一输出 `stem.glb`、正／左／背／右透明图和缩略图，原始 `.blend` 与参考照片另外保留。网页封面、编辑素材和真实核名证据保持独立记录。
